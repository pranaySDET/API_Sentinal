
# 🛡️ API Sentinel

### API Regression Monitor — Observe. Compare. Detect.

API Sentinel is a Chrome extension designed to capture API traffic generated by a web application and compare regression runs to identify changes in API behavior, response data, HTTP status codes, and performance.

Instead of relying only on HTTP status codes, API Sentinel helps QA engineers investigate differences between previous and current application behavior using real API request and response evidence.

## 🚀 Why API Sentinel?

During regression testing, an API may return `200 OK` even when the expected business data has not been updated. Comparing API behavior across regression runs can help identify these issues.

API Sentinel aims to make API regression analysis easier by capturing application traffic, storing regression runs, and presenting comparison results in a dashboard.

## ✨ Key Features

- **API Traffic Capture** — Capture API calls made through `fetch()` and `XMLHttpRequest`.
- **Regression Run Management** — Start and stop regression runs and save captured API records.
- **API Comparison** — Compare a previous run with a current run.
- **Status Code Analysis** — Identify new HTTP failures.
- **Response Data Comparison** — Highlight differences in API responses.
- **Performance Comparison** — Identify potential response-time degradation.
- **New and Missing API Detection** — Identify API calls or endpoints that appear in one run but not the other.
- **Request and Response Evidence** — Inspect captured URLs, request payloads, response bodies, status codes, and response times.
- **Sensitive Data Masking** — Mask common sensitive fields before storing or displaying captured data.
- **Interactive Dashboard** — Review regression summaries and investigate individual API records.

> Feature availability and capture coverage may vary by application and browser behavior. See Known Limitations below.

## ⚙️ Installation

1. Clone or download this repository.
2. Open Google Chrome and navigate to `chrome://extensions/`.
3. Enable **Developer mode**.
4. Click **Load unpacked**.
5. Select the `api-sentinel` project folder containing `manifest.json`.
6. Open the target web application in a new tab.
7. Open API Sentinel and click **Start Regression**.
8. Perform the application workflow you want to test.
9. Click **Stop Regression** to save the run.
10. Repeat the same workflow in a second run and select both runs for comparison.

If the extension is reloaded or updated, refresh the application tab so its content script uses the current extension context.

## 📊 Regression Comparison

API Sentinel is designed to help analyze the following categories:

| Category | Purpose |
|---|---|
| Same Behavior | API calls whose compared behavior remains consistent |
| New Failures | Newly observed failed requests |
| Data Changes | Differences in captured response data |
| Performance Issues | Potential response-time degradation |
| New APIs | API calls or endpoints observed in the current run |
| Missing APIs | API calls or endpoints present previously but absent from the current run |

### API Calls vs. Unique APIs

These are different metrics:

- **API Calls:** Total number of captured request occurrences in a run.
- **Unique APIs:** Number of distinct API identities, typically based on HTTP method and normalized URL.
- **Compared Calls:** Request occurrences paired for comparison between the selected runs.

For example, calling `GET /api/patients` five times represents five API calls but may represent one unique API endpoint.

## 🔐 Privacy and Security

API Sentinel may capture request and response data from the target application. Use it only on systems you are authorized to test.

- Do not commit real authentication tokens, cookies, passwords, patient records, or other confidential data.
- Review and sanitize captured data before sharing reports or sample files.
- Masking is best-effort and should not be treated as a guarantee that all sensitive information is removed.
- Avoid committing captured regression data or exported reports to source control.
- Review extension permissions and restrict the target application to the minimum necessary scope for your environment.

## ⚠️ Known Limitations

- The current capture mechanism intercepts `fetch()` and `XMLHttpRequest`; it may not capture every network request.
- Service-worker traffic, WebSockets, browser-level requests, and some cross-origin or frame scenarios may require additional handling.
- Dynamic response values, timestamps, identifiers, and changing application data can affect comparisons.
- API matching and repeated-call pairing depend on the comparison implementation and the order in which requests occur.
- Extension reloads may invalidate content scripts in already-open tabs; refresh the application tab after reloading the extension.
- Sensitive-data masking is not a substitute for avoiding the capture or sharing of confidential information.
